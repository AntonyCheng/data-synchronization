# SeaTunnel 作业生命周期实施计划

## 目标

在现有数据源管理、同步任务校验和配置预览基础上，完成单表 MySQL -> PostgreSQL `FULL_CDC` 任务的最小可运行闭环：

`草稿 -> 提交 -> 运行中 -> 暂停/停止 -> 恢复 -> 状态刷新`

本迭代不扩展多表编排、定时调度、主动告警和自动 DDL；增加启动恢复扫描和只读行数核对作为稳定性基线。

## 设计边界

- SeaTunnel Zeta REST API 2.3.13 是作业控制入口：`/submit-job`、`/job-info/{jobId}`、`/stop-job` 和 `/jobs/checkpoints/{jobId}`。
- HOCON 配置通过 `POST /submit-job?format=hocon&jobName=...` 的纯文本请求体提交，不把配置文件落到平台磁盘。
- 暂停使用 `stop-job` 的 `isStopWithSavePoint=true`；恢复使用相同 `jobId`、相同配置和 `isStartWithSavePoint=true`。
- 平台元数据库只保存 `engine_job_id`、配置指纹、最近检查点摘要和错误信息，不保存包含密码的明文引擎配置。
- 引擎返回状态统一映射到平台状态；引擎不可达或作业不存在时必须显示异常，不得伪造为运行中。
- 只操作 `test/` 隔离 POC 的 SeaTunnel、MySQL 和 PostgreSQL 容器，不能触碰现有业务容器。

## 实施步骤

1. 元数据扩展：增加配置指纹、最近检查点 ID/时间/状态字段，并补充作业操作权限菜单。
2. 后端适配器：封装 REST 请求、响应解析、超时和错误脱敏。
3. 任务服务：实现提交、状态刷新、暂停、恢复、停止；状态变更与引擎调用保持一致。
4. 前端任务页：增加操作按钮、状态展示、引擎作业 ID 和错误信息，运行中禁止编辑/删除。
5. 验证：启动隔离 POC，创建一条任务，执行初始快照、CDC 增删改、暂停恢复和停止，保存结果证据。
6. 稳定性补强：引擎不可达落为 `FAILED`，应用启动扫描遗留运行任务，提供 `/check` 行数核对和前端结果弹窗。

## 验收标准

- 提交成功后任务有 SeaTunnel `jobId`，状态为运行中。
- 状态刷新能反映运行、失败、已停止和已暂停，不依赖页面本地状态。
- 暂停后源端新增数据不会写入目标；恢复后该数据最终写入目标且不重复全量。
- 停止后不会继续消费 binlog；再次恢复必须明确使用 checkpoint/savepoint。
- API 和日志不返回数据源密码或完整未脱敏配置。
- 引擎不可达时任务状态为 `FAILED`，引擎恢复后可以重新启动；源/目标行数核对结果可在页面查看。
