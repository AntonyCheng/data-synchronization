# 单表任务创建向导

## 目标

单表同步任务采用五步创建向导，确保用户在提交前完成数据源连接、源表元数据、目标端策略、字段选择和同步方式确认。向导只负责单表任务；多表和整库同步从“同步任务组”进入。

## 五步流程

1. **数据源**：选择 MySQL 源和 PostgreSQL 目标。选择源后立即执行轻量 JDBC 连接测试、数据库/表探查，并执行 MySQL CDC 前置检查。连接失败时不能进入下一步。
2. **同步粒度**：单表入口选择一个源表。页面展示字段数、字符集、主键和可靠非空唯一键；没有可靠同步键的表只能创建全量任务。
3. **目标端**：填写目标 schema/表名并选择全量数据策略。目标表已存在时，启动前必须通过字段、类型、同步键和额外必填列兼容检查。
4. **字段映射**：MVP 只支持同名字段映射和排除非同步键字段。同步键必须是主键，或所有列均为 `NOT NULL` 的唯一索引，并且必须包含在所选字段中。
5. **同步方式**：选择任务名称、全量/纯增量/全量 + CDC、DDL 策略、调度和源库保护参数。末屏展示汇总信息和风险提示，确认后提交。

## 纯增量启动位点

纯增量不会补齐任务创建前的历史数据，目标端必须已有可信基线。启动策略与 SeaTunnel 2.3.13 MySQL-CDC connector 对应：

| 平台选项 | SeaTunnel 配置 | 规则 |
|---|---|---|
| 从最新位点开始 | `startup.mode = "latest"` | 不填写额外位点 |
| 按时间开始 | `startup.mode = "timestamp"`、`startup.timestamp` | 使用源端 Asia/Shanghai 的 `LocalDateTime`，转换为毫秒 epoch；不能晚于当前时间 |
| 指定 binlog 位点 | `startup.mode = "specific"`、`startup.specific-offset.file`、`startup.specific-offset.pos` | 文件名只允许字母、数字、`.`、`_`、`-`；位置必须 `>= 4` |

非纯增量任务会清空这些位点字段并固定为 `LATEST`，避免无效配置残留。保存时服务端会重新校验模式、时间、文件名和位置；前端限制不能替代服务端校验。

## 提交流程与验收

最终提交仍由后端重新探查元数据并执行综合校验。纯增量必须通过 CDC 前置检查；任务创建成功后配置版本从 1 开始，修改草稿或已停止任务生成新版本。配置快照只保存无凭证语义，不保存密码。

验收至少覆盖：五步前进/回退不丢字段、无可靠同步键时增量选项不可用、三种位点都生成正确 HOCON、未来时间/非法文件名/小于 4 的位置被拒绝、非增量任务不会携带位点，以及刷新后编辑任务能正确回填向导字段。
